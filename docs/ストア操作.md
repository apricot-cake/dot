# ストア操作

現在はストア提出を保留しています。MSIX と拡張機能 ZIP は同じコミットから作成し、組み合わせて検証します。両方のバージョンは独立して管理します。登録・提出の状況は [配布とストア提出](配布とストア提出.md)、Chrome ウェブストアの掲載情報と申告は [Chrome ウェブストア掲載](Chromeウェブストア掲載.md) にまとめています。

## 検証と成果物

ローカルで拡張機能の提出用ビルドを検証するには、次を実行します。

```powershell
pnpm run release:ext:verify
```

出力先は `extension/.output/chrome-mv3-release/` です。拡張機能は `pnpm run ext:package` で ZIP にします。ZIP 内の manifest からは開発用 ID 固定の `key` を除去し、通常ビルドの鍵は保持します。提出用 ZIP の正式 ID は Chrome ウェブストアが管理します。

`配布パッケージの検証` ワークフローを main で手動実行します。対象コミットの CI と App tests の成功を先に確認します。既定の `verification` は検証専用の識別情報を使うため、本番提出には使用できません。

`store` を選ぶ前に、両ストアで取得した識別情報を、GitHub のリポジトリ変数（Repository Variables）へ設定します。

- `DOT_MSIX_IDENTITY_NAME`
- `DOT_MSIX_PUBLISHER`
- `DOT_MSIX_PUBLISHER_DISPLAY_NAME`
- `CHROME_EXTENSION_ID`

`CHROME_EXTENSION_ID` は、Chrome ウェブストアで確定した拡張機能 ID を設定する共通の Repository Variable です。Store 用 MSIX はこの ID を読み取り専用の配布情報へ同梱し、初回起動からホストの接続許可に使います。利用者が ID を入力する必要はありません。

成果物には MSIX・ZIP と `release.json` を含めます。記録にはコミット SHA、チャンネル、両方のバージョン、ファイルごとの SHA-256 を保存します。`store` では、アプリへ同梱した拡張機能 ID も保存します。`verification` ではこの値を `null` とします。ストアの変更操作では、この ID と提出先 ID の一致も確認します。提出時に再ビルドせず、この成果物を検証して使います。

配布前にはクリーンな Windows 環境で、アプリの起動、拡張機能からの保存、ライブラリの作成と既存ライブラリの読み込みを確認します。生成成功だけでは実機検証の完了にはなりません。MSIX の導入・起動・保存・検索・更新・削除後のライブラリ保持と、対応する拡張機能からの接続・保存を確認します。

## 初期登録と認証

Microsoft Store の製品登録と Chrome ウェブストアの初期掲載情報は、各開発者ダッシュボードで設定します。価格、公開範囲、権限の申告、年齢区分、審査用手順を確認します。Microsoft Store の初回提出は Partner Center での設定が必要です。更新 API から新規製品や初回掲載情報を作成する処理は設けません。

GitHub Actions の実行先と承認設定を管理する Environment は、`microsoft-store` と `chrome-web-store` に分け、main のみ許可し、所有者の承認を必須にします。GitHub と各サービスの認証を連携する OIDC の信頼条件も、所有リポジトリと対応する Environment に限定します。

| Environment | Variables | 外部側の設定 |
| --- | --- | --- |
| `microsoft-store` | `AZURE_CLIENT_ID`、`AZURE_TENANT_ID`、`MICROSOFT_PRODUCT_ID` | Entra のフェデレーション資格情報と Partner Center のアプリ権限 |
| `chrome-web-store` | `GOOGLE_WORKLOAD_IDENTITY_PROVIDER`、`GOOGLE_SERVICE_ACCOUNT`、`CHROME_PUBLISHER_ID` | Workload Identity Federation と Chrome ウェブストアのサービスアカウント登録 |

長期のクライアントシークレットやサービスアカウント秘密鍵は使用しません。認証後のアクセストークンだけを、その操作に渡します。

## 手動操作

`ストア操作` ワークフローは main で手動実行します。既定の `status` は読み取りだけです。変更操作には、パッケージの実行 ID と対象コミット SHA、Environment の承認が必要です。

| 操作 | Chrome ウェブストア | Microsoft Store |
| --- | --- | --- |
| `status` | アップロード・審査・公開状態の取得 | 指定または現在の提出状態の取得 |
| `upload` | 検証済み ZIP のアップロード | 指定した既存下書きへ検証済み MSIX をアップロード |
| `submit` | ZIP をアップロードし、審査後の公開待ちで提出 | 既存下書きへ MSIX をアップロードし、Manual のまま審査提出 |
| `publish` | 承認済みの公開待ちバージョンを照合して公開 | Partner Center の Publish now で別途操作 |

変更操作は `STORE_SUBMISSIONS_ENABLED=true` を Environment に設定するまで拒否します。現在は設定しません。通常の push・タグ作成でストアを操作する経路はありません。

Microsoft の下書き ID は Partner Center で内容を確認して指定します。掲載情報を保持し、下書きの自動作成・削除は行いません。公開方式が Manual、公開対象が Public であることを確認してから更新します。接続確認だけの操作では下書きを変更しません。

変更 API の成否が不明な場合は、状態を先に確認します。変更リクエストを自動再送しません。Chrome の非同期アップロードについては、同じ実行内で読み取り API により完了を待ちます。

初回公開はアプリを先に公開し、入手できることを確認してから拡張機能を提出します。アプリは Public audience・検索非表示・直接リンクから入手可能とし、Chrome 審査員へ Store リンクと操作手順を案内します。審査承認と公開完了は、ワークフローの成功とは別に確認します。
