# Chrome ウェブストア掲載

Chrome ウェブストアの開発者ダッシュボードへ入力する掲載情報と申告の案を、根拠とともにまとめます。ダッシュボードには入力履歴が残らないため、申告内容はこの文書で管理します。登録・提出の状況と残る作業は [配布とストア提出](配布とストア提出.md)、提出の操作は [ストア操作](ストア操作.md) で扱います。

## 掲載名と説明

掲載名は `dot` です。名称と要約は [英語のマニフェスト翻訳](../extension/public/_locales/en/messages.json) と [日本語の翻訳](../extension/public/_locales/ja/messages.json) を管理元とします。既定の言語は英語で、日本語も掲載します。

詳細説明の原稿は [日本語](store-description.ja.txt) と [英語](store-description.txt) を参照し、この文書へ複製しません。単一目的の申告案は「ウェブで見つけた投稿や画像を、出典とともに端末上のライブラリへ保存する」です。カテゴリーは Productivity を候補とし、ダッシュボードの現行選択肢で確定します。

## アイコンと掲載画像

| 素材 | 寸法 | 状態 |
| --- | --- | --- |
| [ストア用アイコン](../extension/public/icons/icon128.png) | 128 × 128 | 既存素材あり |
| 拡張機能用の icon16・icon32・icon48 | 各 16・32・48 px の正方形 | manifest の参照先と一致 |
| 掲載用スクリーンショット | 1280 × 800 または 640 × 400 | 未準備。保存操作と通知が分かる実画面を、公開可能なサンプルで撮影する |
| 小さいプロモーション画像 | 440 × 280 | 未準備 |
| 大型プロモーション画像・動画 | 1400 × 560 | 任意。未制作 |

[サイトの共有用画像（OG 画像）](site/public/og.png) は 1200 × 630 で、掲載画像の寸法と異なります。サイトの画像や操作デモは静的な再現なので、実画面のスクリーンショットとして使いません。

## 権限の申告案

対象は [WXT の manifest 設定](../extension/wxt.config.ts) と、そこから生成した Manifest V3 です。各権限は次の機能に使います。

| 権限 | 理由 |
| --- | --- |
| `activeTab` | 利用者がツールバーや右クリックで保存を指示したページへ一時的にアクセスし、選択した投稿・画像と出典を取得する |
| `scripting` | 保存操作の UI、投稿情報の読み取り、保存結果の通知をページへ挿入する。対応サイトでは起動・更新後にも保存ボタンを表示する |
| `nativeMessaging` | 利用者の PC 上の dot へ保存要求を送り、保存結果と保存済み状態を確認する |
| `storage` | 表示設定、保存履歴、診断記録、ホストへ未送信の保存要求を端末上に保持する。同期ストレージは使わない |
| `contextMenus` | 画像・動画を右クリックから保存できるようにする。ブックマークなどの一覧ページでは、取り込みモードを開始する項目に切り替える |
| `alarms` | 診断ログが短時間に集中した場合に、送信制限で保留した診断処理を再開する。未送信の保存要求を再送するための権限ではない |
| `https://cdn.syndication.twimg.com/*` | X の公開投稿情報を取得し、本文・作者・メディアなどを保存へ含める |
| `https://x.com/*` | X のページで投稿を検出し、保存ボタンと保存済み表示を提供する。ブックマークと履歴のページでは取り込みモードを提供する |
| `https://twitter.com/*` | X の旧ドメインで同じ投稿保存・保存済み表示・取り込みモードを提供する |
| `https://bsky.app/*` | Bluesky のページで投稿を検出し、保存ボタンと保存済み表示を提供する。保存済み投稿のページでは取り込みモードを提供する |
| `https://www.pixiv.net/*` | pixiv の作品ページに保存操作を表示し、作品・作者の詳細を取得する。一括取り込みでは個人設定 API からログイン中のユーザー ID を取得し、本人のブックマーク一覧であることを確認する。閲覧中のログインセッションを pixiv への要求に使う |
| `https://pixiv.net/*` | pixiv の別ホスト表記でも作品の保存操作と保存済み表示を提供する |

リモートコードの申告案は「使用しない」です。実行するスクリプトは拡張機能へ同梱し、外部から取得する投稿情報はデータとして扱います。最終 ZIP の内容と申告を提出前に照合します。

## データ利用の申告案

通信と保存の詳細は [プライバシーポリシー](PRIVACY.md) です。開発者が利用者のデータを受信・収集しないことと、拡張機能がページ内容を読み取って端末へ保存することは別です。「開発者のサーバーへ送信しない」だけを根拠に、データ利用欄をすべて非該当にしません。

| データ分類 | 実際の処理と回答案 |
| --- | --- |
| Website content | 該当。本文、画像・動画 URL、ページのメタデータを保存のため読み取る。端末上の dot へ渡し、未送信時は端末上のキューへ一時保存する |
| Web history | 該当と判断する案。保存対象の出典 URL、日時、最近の保存履歴を扱う。公式 FAQ は利用者が要求・操作するウェブ資源の URL を閲覧活動に含める。利用者が X の履歴ページで取り込みモードを開始した場合は、そのページに表示された投稿を保存する。ブラウザの閲覧履歴は取得しない。現行フォームの定義と照合して確定する |
| User activity | 該当と判断する案。保存操作の開始・結果と時刻を診断記録として端末に保持する。現行フォームの操作記録の定義と照合して確定する |
| Personally identifiable information | 該当。投稿者の表示名・ハンドルを投稿情報として扱う。一括取り込みでは pixiv のログイン中ユーザー ID も取得する。公式 FAQ は氏名、username、account number をこの分類に含める |
| Authentication information | 未確定。pixiv への要求にはブラウザがセッションクッキーを付けるが、拡張機能はクッキーを直接読み出したり保存したりしない |
| Health・Financial・Personal communications・Location | これらを独立して収集する機能はない。利用者が保存するページに含まれ得る情報との区別を確認し、申告を確定する |

[公式 User Data FAQ の質問 2〜4](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)は、ページの切り抜き・読み取りをデータの取り扱いに含め、端末内だけの処理・保存も申告対象としています。上表はこの定義と現コードを照合した結果です。確認箇所は `extension/utils/extractor/pixiv.ts` の `fetchPixivSelfUserId`、各 extractor の投稿者情報、`extension/utils/background.ts` の保存・診断記録です。未確定の分類を推測で入力しません。

外部通信は投稿元への情報取得とメディア取得で、保存内容を開発者へ送る経路はありません。データを販売しない、主目的以外に使わない、信用評価・融資に使わないという認証項目は、現実装に基づき同意する案です。

## URL と開発者情報

プライバシーポリシーの公開 URL は `https://apricot-cake.github.io/dot/privacy/`、ホームページは `https://apricot-cake.github.io/dot/` とします。サポート URL は `https://github.com/apricot-cake/dot/issues` を使う案です。

開発者表示名と公開する連絡先メールは、登録済み開発者アカウントの設定を確認して確定します。値を推測して記載しません。

## パッケージ

`pnpm run ext:package` で提出用 ZIP を作成します。ストアが拡張機能 ID と署名を管理するため、ZIP 内の `manifest.json` からは開発用 ID を固定する `key` を除きます。`key` を含む ZIP はアップロード時に拒否されます。通常ビルドと開発用プロファイルの固定鍵は保持します。[開発時の ID と公開鍵の公式説明](https://developer.chrome.com/docs/extensions/reference/manifest/key)

正式な拡張機能 ID はストアで取得し、[ストア操作](ストア操作.md) の設定と MSIX の配布情報へ反映します。開発用の固定 ID を正式 ID として扱いません。

## 配布設定と審査用手順

無料で配布します。公開範囲・地域・成人向け分類は未確定です。Microsoft Store 側との公開順序は [配布とストア提出](配布とストア提出.md) に従います。

審査員向けには、アプリ導入、拡張機能追加、保存先選択、対応サイトでの保存、アプリでの確認という手順を案内します。手順に載せる Windows アプリの Store リンクは、アプリの公開準備で確定します。
