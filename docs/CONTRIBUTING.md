# 開発に参加する

この文書では、開発環境の準備、アプリと拡張機能の起動、検証、配布物の作成を説明します。構成は [アーキテクチャ.md](アーキテクチャ.md)、表示言語は [ローカライズ.md](ローカライズ.md)、テストの選び方は [テスト.md](テスト.md) を参照してください。

## 準備

Windows、Chrome、Node.js 24.16.0 が必要です。対応するバージョン管理ツールでは、リポジトリ直下の `.node-version` を読みます。手動で設定する場合も同じバージョンを使ってください。

pnpm 12.11.2 を使います。Windows で未導入の場合は、[公式のインストール手順](https://pnpm.io/installation)に従って `npx get-pnpm` を実行してください。バージョンはルートの `package.json` の `packageManager` で固定しています。

リポジトリのルートで、最初に次を実行します。

```powershell
pnpm install --frozen-lockfile
pnpm run setup
```

`pnpm install` はルート、`app/`、`extension/`、`docs/site/` を一つのワークスペースとして準備します。Electron Forge の配布処理に合わせて `nodeLinker: hoisted` を使い、`hoistingLimits: workspaces` で各プロジェクトの依存関係をそれぞれのディレクトリ内に配置します。依存関係はルートの `pnpm-lock.yaml` で管理し、依存パッケージのビルド許可は `pnpm-workspace.yaml` の `allowBuilds` で指定します。`pnpm run setup` は Electron の実行環境を準備します。新しいワークツリーでも、そのワークツリーごとに両方を実行してください。

アプリを起動したまま依存関係を更新しないでください。使用中のネイティブモジュールを更新すると、インストールが失敗したり依存関係が不完全になったりします。

## 文章とスペルのチェック

Markdown の検査には `markdownlint-cli2`、ソースと文書のスペル検査には `typos` を使います。Markdown の依存関係は `pnpm install` で入ります。typos は [公式リリース](https://github.com/crate-ci/typos/releases/tag/v1.50.3) の v1.50.3 を PATH の通った場所に配置するか、Rust 環境で次を実行してください。

```powershell
cargo install typos-cli --version 1.50.3 --locked
```

```powershell
pnpm run lint:markdown
pnpm run lint:typos
```

`pnpm run lint` と `pnpm run check` でも両方を実行します。CI では markdownlint を既存のチェックに含め、typos は公式 Action で実行します。検査はファイルを書き換えません。Markdown の自動修正は `pnpm run lint:markdown:fix` で実行できます。

設定は `.markdownlint-cli2.jsonc` と `_typos.toml` にあります。生成物・依存物は Git の除外設定に従い、第三者ライセンスの原文とロックファイルはスペル検査から除外します。日本語の段落や表を文字数だけで折り返さないため、Markdown の行長制限は無効にしています。意図的な誤字を使う検索テストは、テストファイルに限って例外を設定します。

## 開発・実機検証の進め方

開発と実機検証は main の主作業ツリーで一件ずつ進めます。アプリと拡張機能を変更したら、対象をデプロイしてから既存の開発用アプリと Chrome で確認します。開発用 Chrome のプロファイルとログイン状態は継続して使います。

通常の確認には普段のライブラリを使います。テストデータの保存・削除には下記のサンドボックスと検証専用タブを使います。自動テストや CI の並列実行はそのまま利用できます。

## デスクトップアプリを起動する

普段のライブラリを使う開発版は、リポジトリのルートで起動します。

```powershell
pnpm start
```

このコマンドは、すでに配備された `app/out/` を起動します。初回、またはソースを変更した後は、先に `pnpm run app:deploy` を実行してください。`scripts/start-dot.cmd` も同じ起動を行います。PowerToys のコマンドパレットなどから起動する場合は、この `.cmd` ファイルをそのまま登録してください。すでに開発版が起動している場合は、新しいウィンドウを作らず既存のウィンドウを前面に出します。

開発版を起動して CDP 接続も確認する場合は、次を使います。

```powershell
pnpm run app:debug
```

このコマンドは起動中の開発版を通常終了し、普段のライブラリを使うアプリを背面で起動します。CDP はコマンドが所有する継承 pipe で接続し、TCP ポートは公開しません。Ctrl+C でアプリと HMR サーバーを通常終了します。実ライブラリを扱うため、検証用データを保存する操作には使わないでください。

画面を撮る場合は `pnpm run app:debug shot`、式を評価する場合は `pnpm run app:debug eval "<式>"` を使います。操作後にセッションを通常終了します。連続した操作は `run <モジュール>` で `run(session, args)` を export する検証モジュールを実行してください。画像は既定で `%LOCALAPPDATA%\dot\verification` に保存されます。リポジトリ内を出力先には指定できません。実ライブラリを表示したキャプチャは、公開物へ添付しないでください。

画面を継続的に調整し、レンダラーの HMR を使う場合だけは次を実行します。

```powershell
pnpm run app:dev
```

通常の起動に開発サーバーは必要ありません。

### ショートカットで使うアプリへ反映する

チェックアウトの変更を、普段使う開発版へ反映するときは次を実行します。

```powershell
pnpm run app:deploy
```

成功したビルドだけを `app/out/` に配備します。起動中のアプリは、取り込みやバックアップなどの処理が終わった後に再起動します。アプリを閉じている場合は、次回の起動から新しい出力を使います。`pnpm run app:build` はビルドだけを行い、起動中のアプリには反映しません。

### 隔離した環境で確認する

実ライブラリを変更したくないときは、サンドボックスを使います。フィクスチャのライブラリと専用の設定ディレクトリで HMR 開発版を一つ起動します。主作業ツリーから実行し、同じコマンドが pipe 接続を所有します。

```powershell
node scripts/sandbox-app.cts
```

停止するときは起動したコマンドで Ctrl+C を押します。操作後に終了する場合は、次のように同じコマンドへ指定します。

```powershell
node scripts/sandbox-app.cts start -- eval "document.title"
```

フィクスチャでは再現しない表示や性能だけを確認したい場合は、実ライブラリの読み取り用コピーから起動できます。

```powershell
node scripts/sandbox-app.cts start --real
```

このモードの画面には実データが含まれます。スクリーンショットを Issue やプルリクエストへ貼らないでください。

## Storybook で画面を確認する

dot の React 画面を、普段の実ライブラリから読み取り専用でブラウザに表示します。リポジトリのルートで起動してください。

```powershell
pnpm run storybook
```

[Storybook](http://127.0.0.1:6006/) で「dot → 画面 → ライブラリ」を選びます。サイドバーや設定を操作して、確認したい画面へ移動できます。画面だけを表示するには、Storybook の「Open canvas in new tab」を使うか、次の URL を開いてください。

```text
http://127.0.0.1:6006/iframe.html?id=dot-screen--library&viewMode=story
```

Codex の内蔵ブラウザでこの URL を開き、「Annotate」で要素や範囲を選んでコメントします。その後、チャットでコメントへの対応を依頼してください。

通知を繰り返し確認するには「dot → 通知」の[アプリ内](http://127.0.0.1:6006/iframe.html?id=dot-notifications--app&viewMode=story)または[拡張機能の保存](http://127.0.0.1:6006/iframe.html?id=dot-notifications--extension&viewMode=story)を開きます。各ボタンから本番の部品と文言で通知を表示し、進行中・完了・失敗を切り替えられます。消去ボタンで表示をリセットできます。保存や削除などの実処理は実行しません。件数は表示確認用です。

画面はアプリ本体のコンポーネントとスタイルを共有します。開発サーバーが開発版アプリの設定から保存先を読み、データベースを読み取り専用で開きます。画像・動画は元ファイルから必要な分だけ配信するため、ライブラリのコピーは作りません。最新の投稿情報を読み直すには、ページを再読み込みしてください。

検索、画面移動、拡大表示などの閲覧操作を使えます。投稿・タグ・設定の保存、削除、インポート、閲覧履歴の記録は実行しません。サーバーのライブラリ参照用 API は `127.0.0.1` の同一オリジンからの GET/HEAD だけを受け付け、投稿やプロフィールが参照するメディアだけを配信します。実ライブラリを読み込めない場合は、サンプルへ切り替えずにエラーを表示します。

実データは開発サーバーの実行時だけ読み込み、静的ビルドには含めません。静的ビルドだけでは実ライブラリのプレビューを利用できません。画面には実データが含まれるため、スクリーンショットを公開物へ添付しないでください。Electron 固有の動作の確認は、デスクトップアプリを背面で起動して行います。

うごイラはプレビュー用の静止画で表示します。再生はデスクトップアプリで確認してください。

型検査と静的ビルドは次のコマンドで実行できます。型検査は `pnpm run typecheck`、静的ビルドは CI のチェックにも含まれます。

```powershell
pnpm run storybook:check
pnpm run storybook:build
```

## 拡張機能を開発する

拡張機能を変更したら、共有のリリースビルドを配備します。

```powershell
pnpm run ext:deploy
```

このコマンドは `extension/.output/chrome-mv3/` にビルドを作り、同じ開発用プロファイルを背面で起動して読み込み直します。終了時に開発用 Chrome を通常終了します。日常用 Chrome には、ネイティブ メッセージングホスト経由で更新を通知します。

開発用 Chrome の初回準備では、開発用ネイティブ メッセージングホストを登録します。

```powershell
pnpm run ext:dev:register
```

このコマンドは HKCU と開発用設定ディレクトリへ書き込みます。Chrome と同じ Windows ユーザーで実行してください。

開発用プロファイルを開くには、次を実行します。

```powershell
pnpm run ext:dev:open
```

開発用 Chrome は管理ランチャーが非表示のセッションを pipe 接続で操作し、TCP の CDP 接続口を公開しません。コマンド終了時に Chrome も通常終了します。ログインと保存先を維持し、次の起動で前回のタブを復元しますが、ページ内の一時的な状態は引き継げません。セッションを保持したコマンドがある場合は、Ctrl+C で終了してから次のコマンドを実行してください。

開発用 Chrome の通常タブは普段のライブラリを使います。隔離した保存先が必要な確認では、通常タブの設定を変更せず、検証用のアプリとタブを開く専用スクリプトを使ってください。

```powershell
node scripts/verify-extension-tab.cts <投稿 URL>
```

検証タブを使う間は、このコマンドを実行したままにします。終了時に検証タブと専用の保存先設定を片付けます。通常タブの設定は変更しません。

自動検証では、`node scripts/run-dev-browser.cts <検証モジュール> [引数...]` を使います。検証モジュールは `run({ context, browser, args })` を公開し、渡されたセッション内で操作します。

開発用 Chrome への接続状態とプロファイルの場所は、次で確認できます。

```powershell
pnpm run ext:dev:status
```

日常用 Chrome や一般的なブラウザ操作用の拡張機能には接続しません。

## UI 部品を変更する

アプリの共通 UI は `app/src/renderer/src/components/ui/` で管理します。shadcn/ui の Base UI 版を使い、画面側では候補・値・処理とレイアウトを指定します。色、余白、フォーカス、候補面の配置を各画面に複製しないでください。

| 用途 | 部品 |
| --- | --- |
| 決まった候補から選ぶ | `Select` |
| 候補を検索して選ぶ | `Combobox` |
| 自由入力と入力候補 | `Autocomplete` |
| 操作の一覧 | `DropdownMenu` |
| 複数の操作や内容を含む補助面 | `Popover` |

通常のボタン・入力欄・タグ表示には `Button`・`Input`・`Badge` を使います。入力内のアイコンやボタンは `InputGroup` で組み合わせます。`SelectItem` は `SelectGroup`、メニュー項目は対応するグループ内へ置きます。画像カードやリサイズハンドルなど、通常のフォーム部品と用途が違う操作は専用の構造を保ちます。

## 検証する

通常の変更後は、次を実行します。

```powershell
pnpm run check
```

拡張機能、保存処理、IPC、画面など、変更した対象に応じて追加の検証を行います。コマンドの選び方、ビルドの前提、実行方法は [テスト](テスト.md) を参照してください。

実機確認に入る前に、変更した対象を配備してください。アプリだけを変更した場合は `pnpm run app:deploy`、拡張機能だけを変更した場合は `pnpm run ext:deploy`、両方を変更した場合は両方を実行します。

## 保存に失敗したとき

まず、拡張機能とアプリが想定した環境を使っていることを確認します。その後、通常版の `%APPDATA%\dot` と開発用の `%APPDATA%\dot-Dev` のログを確認します。

1. 拡張機能の診断ページでホストへ接続できているかを確認します。
2. アプリのログで取り込みキューと SQLite への取り込みに失敗していないかを確認します。
3. ホストのログで保存先、メディアのダウンロード、メッセージ形式のエラーを確認します。

個人情報や認証情報をログや Issue に含めないでください。

## アイコンを更新する

元画像 `assets/icon-master.png` を差し替えた後、リポジトリのルートで次を実行します。

```powershell
node_modules/.bin/electron scripts/make-icons.cjs
```

正方形で 512 px 以上の元画像を使ってください。
